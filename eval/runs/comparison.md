# M6：本機 qwen3.5:9b、Claude Opus 5.5、Claude Haiku 5.5 比較

測試資料：12 件模擬請款案（160 頁、416 個欄位），涵蓋正常、缺件、金額／幣別不符、PO 號打錯、未簽核、掃描檔歪斜、廠商別名等情境。
評測日期 2026-11-24。三者使用同一套提示詞與規則；Claude 為 `effort: low`，qwen 為 `think: false`、溫度 0。

## 欄位擷取

| 項目 | qwen3.5:9b（本機 Ollama） | Claude Opus 5.5 | Claude Haiku 5.5 |
|---|---|---|---|
| 分頁正確 | 160/160 | 160/160 | 160/160 |
| 欄位正確（原始） | 416/416 | 416/416 | 413/416（99.3%） |
| 欄位正確（金額解析強化後） | 416/416 | 416/416 | 416/416 |
| 總時間 | 1,566 秒（約 130 秒／件） | 321 秒（約 27 秒／件） | 240 秒（約 20 秒／件） |
| 掃描檔（C10） | 256 秒 | 54 秒 | 45 秒 |
| tokens（輸入／輸出） | — | 227,395／19,054 | 227,395／28,485 |
| 費用（12 件） | 0（電費與硬體另計） | USD 1.29（約 0.11／件） | USD 0.037（約 0.003／件） |

Haiku 唯一的錯在掃描檔 C10：把影像上的「46,200.00」讀成「46.200.00」，三個金額欄位因此被解析成 46.2。
Opus 與 qwen 都讀對，所以這是 Haiku 看掃描影像較弱，不是程式問題。

處理方式是讓金額解析依分隔符號位置判斷：最後一段是兩位數就當小數點（`46.200.00`、`46.200,00` → 46,200），
只有同一種符號、最後一段三位數才當千分位（`1.234.567` → 1,234,567）。強化後三者皆 416/416。
即使沒有這個修正，金額也會和 SAP PO 比對不上而被判為「待廠商補件」，結果是多一封需要人看的信，不會讓錯誤金額通過送簽。

## 信件開頭段落（9 封：5 封補件信、4 封內部信）

| 項目 | qwen3.5:9b | Claude Opus 5.5 | Claude Haiku 5.5 |
|---|---|---|---|
| 通過檢查（數字、性別稱謂、長度） | 9/9 | 9/9 | 9/9 |
| 事實錯誤 | 0 | 0 | 0 |
| 語氣與可讀性 | 偏公文、生硬，3 封寫成「致某某您好」 | 最自然，會說清楚細節在哪、要對方做什麼 | 通順，偶有贅句（「隼光科技股份有限公司敬請您儘速處理」） |
| 費用 | 0 | USD 0.05 | USD 0.003 |

這輪比較順便修掉三個問題，所有模型都適用：

1. 會依名字猜性別寫「先生／小姐／Mr.」→ 提示詞禁止，並加檢查，違反就退回範本。
2. 會說「附件清單」，但清單其實在信件內文 → 提示詞說明清單在下方。
3. 英文信用了中文公司名 → 設定新增 `company.name_en`，英文信改用英文名。

## 建議

- **預設 Claude Opus 5.5**：掃描檔讀得最準，每件約 0.11 美元、27 秒。
- **量大或預算有限選 Haiku 5.5**：每件約 0.003 美元、最快，模擬資料上強化解析後同樣全對；掃描檔較多的情境建議先用真實樣本驗證。
- **文件不能出公司選本機 Ollama**：準確率相同，但每件約 2 分鐘。
- 三者在「模型設定」頁都可以直接切換。

模擬 PDF 版面乾淨，真實廠商文件（手寫、印章壓字、表格跨頁）可能拉開差距，需要用真實樣本再測。
