# 稽核規則、寄信路由與信件

## 稽核規則

規則定義在 `00_設定/稽核規則.yaml`，每條規則都有「負責方」，決定出問題時該由誰處理。

| 規則 | 檢查內容 | 負責方 |
|---|---|---|
| R01 | 必備文件齊全（發票、PO、承諾書、承認書、規格書、保管單、費用明細） | 廠商 |
| R02 | PO 號各文件一致 | 廠商 |
| R03 | 模具編號各文件一致 | 廠商 |
| R04 | 發票未稅金額 = PO 金額 = 明細表合計（容差 0.5） | 廠商 |
| R05 | 發票幣別與 PO 一致 | 廠商 |
| R06 | 廠商在主檔且狀態有效 | 策購 |
| R07 | 承認書簽核完整（模具設計、品保、ME），判定結果為承認 | 廠商 |
| R08 | 保管人工號在職 | 承辦 |
| R09 | SAP 有 GR 且金額相符 | 承辦 |
| R10 | 未重複請款（應付帳款已付清單＋已處理案件） | 承辦 |
| R11 | 日期合理（PO 日 ≤ 承認日、PO 日 ≤ 發票日） | 廠商 |
| R12 | 發票稅率符合主檔 | 廠商 |
| R13 | 發票賣方與主檔廠商相符（含別名、簡繁） | 廠商 |

### 結果分類

| 結果 | 條件 | 下一步 |
|---|---|---|
| 可送簽 | 全部通過 | 驗收單已填好，承辦確認後送簽 |
| 主檔維護 | 有策購負責的問題 | 通知策購建檔，承辦副本 |
| 待廠商補件 | 有廠商負責的問題 | 寄補件信給廠商窗口 |
| 內部處理 | 只有承辦負責的問題 | 通知承辦（例如先完成 SAP 收貨） |

同時有多種問題時，依 `outcome_priority`（策購 → 廠商 → 承辦）決定。

## 寄信路由

`00_設定/寄信對照表.xlsx` 由部門共同維護，每列是一條規則：

| 欄位 | 說明 |
|---|---|
| 規則編號、啟用 | 停用的列不參與比對 |
| 結果 | 可送簽／待廠商補件／內部處理／主檔維護 |
| 異常規則、廠商代號、產品線 | 比對條件，`*` 代表不限 |
| 收件人、副本 | email 或佔位符 `{PIC}`、`{廠商窗口}`、`{策購負責人}` |
| 維護人、更新日 | 方便追蹤誰改了什麼 |

比對時**最具體的規則優先**（指定越多條件越優先）；同樣具體的多條規則會合併收件人。
收件人有問題（格式錯誤、離職人員）會略過，並在案件頁與 `稽核結果.md` 提示，不會寄錯人。

### 對照表健檢

「設定檢查」頁會列出對照表本身的問題：

- 錯誤：結果名稱打錯、異常規則不存在、沒有收件人、email 格式錯誤、收件人已離職
- 提醒：完全重複的列、條件相同但收件人不同、廠商代號不在主檔
- 建議：維護人已離職

## 信件

| 結果 | 收件人 | 內容 |
|---|---|---|
| 可送簽 | 承辦 | 稽核摘要、驗收單內容，附驗收單 xlsx |
| 待廠商補件 | 廠商窗口（承辦、策購副本） | 需更正事項清單，只列廠商看得懂、該處理的項目，不出現 SAP 等內部資訊 |
| 內部處理／主檔維護 | 承辦或策購 | 稽核發現與建議處理方式 |

- **語言**：英文廠商寄英文信，其餘一律繁體中文。
- **LLM 開頭段落**：`mail.llm_intro` 設定範圍（`internal` 只有內部信、`all` 全部、`off` 全用範本）。
  LLM 寫的段落會檢查：不能出現事實以外的數字、不能用依性別的稱謂（先生／小姐／Mr.）、長度限制；不合格就退回範本。
- **輸出**：`.eml` 存在案件資料夾（Outlook 開啟為可編輯草稿）；`mail.mode: mailpit` 時同時送到模擬信箱。
